Cybersecurity Threats, Vulnerabilities, and Attacks

1.1Common Threats

Threat domains

  • Threat domain — area of control, authority or protection that attackers can exploit to gain access to a system.
  • Ways in: physical access, wireless beyond boundaries, Bluetooth/NFC, malicious email attachments, supply chain, social media accounts, removable media, cloud apps.

Types of cyber threats

Internal vs external

  • Internal — current/former employees, contract partners; accidental or intentional. Can cause greater damage: direct access to premises + insider knowledge.
  • External — amateur or skilled attackers exploiting networked devices or using social engineering.

Domains and their threats

  • User domain — anyone with access to the info system (employees, customers, partners). Weakest link. Threats: no security awareness, poorly enforced policies, data theft, unauthorized downloads/media, unauthorized VPNs (hide data theft), unauthorized websites, destruction of systems/data.
  • Device domain — unattended powered-on devices, downloads from unreliable sources, software vulnerabilities, new malware, unauthorized USB/CD, policy violation, outdated hardware/software.
  • LAN domain — unauthorized access to wiring closets/data centers, OS vulnerabilities, rogue wireless users, exploits of data in transit, mixed server hardware/OS, probing/port scanning, misconfigured firewalls.
  • Private cloud — servers/resources for one organization via Internet. Probing, unauthorized access, router/firewall vulnerabilities & config errors, remote users downloading data.
  • Public cloud — services shared across organizations.
  • Physical facilities — HVAC, water/fire detection, physical security. Threats: weather, unauthorized entry, power outages, social engineering, perimeter breach, theft, unlocked data center, no surveillance.
  • Application domain — critical systems, apps, data. Threats: unauthorized access, server downtime during maintenance, NOS vulnerabilities, data loss, client-server/web app dev vulnerabilities.

Cloud service models

  • SaaS — software centrally hosted, accessed via browser/app.
  • PaaS — platform to develop, run, manage apps on provider’s hardware.
  • IaaS — virtual computing resources (hardware, servers, storage) over the Internet.

Threat complexity

  • APT (advanced persistent threat) — continuous, stealthy, long-term attack, multiple actors/sophisticated malware; targets governments & high-level orgs; well-funded.
  • Algorithm attack — abuses legitimate software algorithms (e.g. energy-tracking) to select targets, trigger false alerts, exhaust RAM/CPU.

Backdoors and rootkits

  • Backdoor (Netbus, Back Orifice) — bypasses normal authentication. Installed via RAT (remote administrative tool) run unknowingly. Access persists even after the original vulnerability is fixed.
  • Rootkit — modifies the OS to create a backdoor; uses privilege escalation; modifies forensic/monitoring tools → hard to detect; usually requires wipe and reinstall.

Threat intelligence sources

  • CVE — dictionary of common vulnerabilities & exposures; sponsored by US-CERT & DHS; maintained by MITRE Corporation.
  • Dark web — encrypted, not indexed; monitored by researchers.
  • IOC (indicator of compromise) — malware signatures, domain names = evidence of breach.
  • AIS (Automated Indicator Sharing) — CISA capability; real-time sharing using STIX and TAXII.

1.2Deception

Social engineering

  • Social engineering — non-technical manipulation of people; exploits human nature.
  • Pretexting — lies to gain privileged data (pretends to need data to confirm identity).
  • Quid pro quo — personal info in exchange for something (gift, free vacation).
  • Identity fraud — stolen identity used to obtain goods/services.

Tactics

  • Authority (fake subpoena), Intimidation (bully, threaten dismissal), Consensus/social proof (everyone does it), Scarcity (limited quantity), Urgency (limited time), Familiarity (rapport, cloned friend profile), Trust (fake security expert).

Other deception

  • Shoulder surfing — looking over shoulder for PINs/codes (also binoculars, cameras).
  • Dumpster diving — searching trash → shred / burn bags.
  • Impersonation — pretending to be someone else (fake IRS); also posting as the victim.
  • Hoax — fake warning (non-existent virus) that spreads fear.
  • Piggybacking / tailgating — following an authorized person into a secure area. Prevent with a mantrap (two doors, outer must close first).
  • Invoice scam — fake invoice → fake login screen.
  • Watering hole — infect sites the organization uses most.
  • Typosquatting — mistyped URL leads to attacker’s look-alike site.
  • Prepending — removing the “external” email tag.
  • Influence campaigns — cyberwarfare: fake news, disinformation, social media.

Defending against deception

  • Never disclose credentials to unknown parties; don’t click enticing links; beware automatic downloads; set & teach security policies; employees own security; resist pressure.

1.3Cyber Attacks

Malware

  • Malware — code to steal data, bypass access controls, harm or compromise a system.
  • Virus — attaches to other files; usually needs user action; can be time-triggered; spreads via USB, downloads, email; mutates. Melissa (1999), $1.2B.
  • Worm — replicates by itself exploiting network vulnerabilities; no host program, no user action after initial infection; slows network. Pattern: vulnerability + propagation + payload. Code Red (2001): 300,000 servers in 19 hours.
  • Trojan horse — masks true intent; uses privileges of the user; does not self-replicate; bound to image/audio/video files.
  • Logic bomb — waits for a trigger (date, DB entry); can destroy hardware by overheating.
  • Ransomware — encrypts data until payment; spread by phishing or vulnerabilities; paying often doesn’t restore data.

DoS / DDoS

  • DoS — interrupts services; easy to conduct. Two types: overwhelming quantity of traffic, maliciously formatted packets.
  • DDoS — from multiple sources: botnet of zombies controlled by handler systems. Signs of infection: slow performance, apps misbehave, pop-up ads.

DNS and URL attacks

  • DNS translates names to IP addresses; monitor domain reputation.
  • DNS spoofing / cache poisoning — false data in the DNS resolver cache → redirect to attacker.
  • Domain hijacking — attacker takes control of DNS info, often by changing admin email (found in public WHOIS).
  • URL redirection — legit redirect abused to send users to malicious site.

Layer 2 attacks

  • Layer 2 = data link layer; ARP resolves IP → MAC.
  • MAC spoofing — device poses as valid one, bypasses authentication.
  • ARP spoofing — links attacker’s MAC to legit IP.
  • IP spoofing — fake source IP.
  • MAC flooding — floods switch with fake MACs.

Other attacks

  • MitM — attacker controls a device and intercepts/relays communication.
  • MitMo (man-in-the-mobile) — controls mobile device, exfiltrates data. ZeuS captures 2-step verification SMS.
  • Replay attack — captures and retransmits messages to bypass authentication.
  • Zero-day — exploits a vulnerability before it’s known/patched; zero hour = moment of discovery.
  • Keylogging — records keystrokes (software or hardware); anti-spyware detects. Can be legitimate (parents).
  • Spoofed email signs: sender domain, link URL, language/spelling, graphics.

Defending against attacks

  • Firewall drops outside packets with inside source addresses; patches current; distribute workload across servers; block external ICMP to prevent DoS/DDoS.

1.4Wireless and Mobile Device Attacks

  • Grayware — unwanted, annoying apps (tracking, ads); hidden in license small print.
  • SMiShing — SMS phishing.
  • Rogue access point — unauthorized AP on secure network; set up via social engineering; used for MitM via deauthentication frames + MAC spoofing.
  • Evil twin — attacker’s AP looks like a better connection → MitM. Defense: VPN on public Wi-Fi.
  • RF jamming — EMI/RFI; jammer must match frequency, modulation and power of the target.
  • Bluetooth — short-range, low-power, PAN, pairing.
  • Bluejacking — sends unauthorized messages/images via Bluetooth.
  • Bluesnarfing — copies data (emails, contacts) via Bluetooth.
  • WEP — no key management, IV too small/readable/static → broken. Replaced by WPA → WPA2. WPA2 key can’t be recovered from traffic, but packet sniffing still possible.
  • Defense: change default config (auth + encryption), place APs outside firewall or in DMZ, detect rogue APs with NetStumbler, guest access policy, remote access VPN for WLAN.

1.5Application Attacks

  • XSS (cross-site scripting) — injected script runs in victim’s browser, steals cookies/session tokens → impersonation.
  • XML injection — manipulates XML queries; corrupt data, access database.
  • SQL injection — malicious SQL in an entry field; app doesn’t filter input → read/modify/destroy data, become DB admin.
  • DLL injection — app tricked into calling malicious DLL.
  • LDAP injection — exploits input validation on LDAP (directory authentication) servers.
  • Buffer overflow — data written beyond buffer limits → crash, data compromise, privilege escalation. ~Half of all exploits (Carnegie Mellon).
  • Remote code execution — run any command with the user’s privileges.
  • Privilege escalation — bug/design flaw/misconfig grants restricted resources.
  • Metasploit — pentest framework; Meterpreter payload runs from memory (evades antivirus), can control webcam.
  • CSRF — unauthorized commands from user’s browser to trusted web app (image tags, hidden forms, JS).
  • Race condition (TOC/TOU) — operations forced simultaneously; threads change shared data at the same time.
  • Improper input handling — unvalidated input → buffer overflow, SQL injection.
  • Error handling attack — error messages reveal hostnames, files, DB/table names.
  • API attack — abuse of an API endpoint.
  • Replay attack — valid transmission repeated/delayed.
  • Directory traversal — read files outside the web root (config files).
  • Resource exhaustion — overwhelms server hardware resources (not bandwidth).
  • Defense: write solid code, treat all input as hostile, keep software updated.

Email and browser attacks

  • Spam — unsolicited email; signs: no subject, asks to update account, misspellings, long/cryptic links, urgent attachment.
  • Phishing — masquerading as legitimate to get info or install malware.
  • Spear phishing — highly targeted, customized to one person.
  • Vishing — voice phishing (VoIP spoofing).
  • Pharming — misdirects to fake version of official website.
  • Whaling — targets high-profile people (executives, politicians, celebrities).
  • Defense: ISP spam filters, antivirus, user education, scan attachments, join APWG (Anti-Phishing Working Group), patch.

Other attacks

  • Physical attacks — infected USB, modified cables with wireless chips, card skimming.
  • Adversarial AI — tainted training data tricks machine learning (misread street signs).
  • Supply chain attacks — intercept third-party supply (e.g. change EOL date).
  • Cloud-based attacks — target data/apps on SaaS, PaaS, IaaS.
Module 2

Securing Networks

2.1Current State of Affairs

  • Kaspersky Cyberthreat Real-Time Map — shows attacks in real time.
  • Network security = business continuity.
  • Cisco Talos — security and threat intelligence. Cisco PSIRT — investigates vulnerabilities in Cisco products (Security Advisories).
  • Attack vector — path by which a threat actor gains access to a server, host, or network (inside or outside).
  • DoS — device/app can no longer serve legitimate users.
  • Internal user can: copy data to removable media/email, compromise servers, disconnect critical links, plug infected USB. Internal threats can cause more damage.
  • Data loss / data exfiltration — data lost, stolen or leaked. Results: brand damage, lost competitive advantage, customers, revenue, litigation, recovery costs. Controlled by DLP (strategic, operational, tactical).

Data loss vectors

  • Email/social networking — most common vector.
  • Unencrypted devices — stolen laptop.
  • Cloud storage — weak security settings.
  • Removable media — unauthorized USB transfer or lost USB.
  • Hard copy — shred.
  • Improper access control — weak/stolen passwords.

2.2Who is Attacking Our Network?

Terms

  • Asset — anything of value (data, IP, servers, devices).
  • Threat — potential danger to an asset.
  • Vulnerability — weakness that could be exploited by a threat.
  • Attack surface — total sum of vulnerabilities accessible to an attacker.
  • Exploit — mechanism to leverage a vulnerability. Remote = over network, no account needed. Local = attacker has user/admin access (not necessarily physical).
  • Risk — likelihood that a threat exploits a vulnerability with undesirable consequence.
  • Countermeasure — action to mitigate a threat or reduce risk.
  • Impact — potential damage caused by the threat.

Risk management

  • Acceptance — mitigation costs more than the risk → no action.
  • Avoidance — eliminate the activity/device (lose its benefits).
  • Reduction — decrease risk; most commonly used.
  • Transfer — to a third party (insurance).

Hackers

  • White hat — ethical; pentests; report vulnerabilities; bounties.
  • Grey hat — commit crimes but not for personal gain/damage; disclose vulnerabilities after compromising.
  • Black hat — unethical criminals for personal gain/malice.
  • Threat actor (course term) = grey or black hat.

Evolution of threat actors

  • 1960s phreaking — audio tones (whistle) to manipulate phone switches.
  • Mid-1980s war dialing — dial every number looking for modems.
  • Script kiddies (1990s) — inexperienced, use existing tools, not for profit.
  • Vulnerability brokers — grey hats who report exploits for rewards.
  • Hacktivists — grey hats protesting political/social ideas (leaks, DDoS).
  • Cybercriminals — black hats for money; underground economy; billions stolen yearly.
  • State-sponsored — steal government secrets, sabotage foreign networks.

Tasks, indicators, sharing

  • Cybersecurity is a shared responsibility. Checklist: trustworthy IT vendor, updated software, regular pentests, backups (cloud + disk), change Wi-Fi password, updated policy, strong passwords, 2FA.
  • IOC (indicator of compromise) — evidence an attack occurred: malware file hashes, IPs, filenames, DNS requests.
  • IOA (indicator of attack) — focuses on attacker motivation and strategies → proactive defense.
  • CISA — US agency; uses AIS to share indicators between government and private sector.
  • NCSA + CISA → National Cybersecurity Awareness Month (October); 2019 theme “Own IT. Secure IT. Protect IT.”
  • ENISA — EU equivalent of CISA.

3.2IP Vulnerabilities

  • ICMP attacks — pings to discover hosts, DoS floods, alter routing tables.
  • DoS / DDoS, address spoofing (blind/non-blind), MiTM, session hijacking (physical access + MiTM).
  • ICMP used for recon: map topology, active hosts, OS fingerprinting, firewall state.
ICMP messageUsed for
Echo request / replyhost verification, DoS
Unreachablenetwork recon & scanning
Mask replymap internal IP network
Redirectssend traffic through compromised device (MiTM)
Router discoveryinject bogus routes
  • Defense: strict ICMP ACL filtering at the edge; IDS/firewalls alert.
  • Amplification & reflection — e.g. Smurf attack; newer: DNS-based and NTP amplification.
  • Resource exhaustion — consume host/network resources.
  • IP spoofing — false source IP; often part of Smurf.
  • Non-blind spoofing — attacker sees traffic; firewall state, sequence-number prediction, session hijack.
  • Blind spoofing — can’t see traffic; used in DoS.
  • MAC spoofing — attacker copies target’s MAC; switch updates CAM table and forwards target’s frames to attacker.
  • Rogue DHCP server — service spoofing → MiTM.

3.3TCP and UDP Vulnerabilities

  • TCP — reliable delivery (ACKs; HTTP, SSL/TLS, FTP, DNS zone transfers), flow control, stateful (three-way handshake).
  • TCP SYN flood — spoofed SYNs, target replies SYN-ACK, waits for ACK → half-open connections overwhelm host.
  • TCP reset attack — spoofed RST tears down connection (normal close = FIN/ACK four-way).
  • TCP session hijacking — spoof IP, predict sequence number, send ACK; can send but not receive.
  • UDP — connectionless, low overhead; used by DNS, DHCP, TFTP, NFS, SNMP, streaming, VoIP. Reliability must be implemented elsewhere.
  • UDP has no encryption; checksum is optional → attacker can alter data and recompute checksum.
  • UDP flood — tools UDP Unicorn, Low Orbit Ion Cannon; sweep ports → server sends ICMP port unreachable → bandwidth used up (like DoS).
Module 4

Attacking What We Do

4.1IP Services

ARP

  • Gratuitous ARP — unsolicited ARP reply; anyone can claim any IP/MAC.
  • ARP cache poisoning — attacker’s MAC mapped to default gateway IP → MiTM.
  • Passive poisoning = steal info. Active = modify/inject data.
  • Tools: dsniff, Cain & Abel, ettercap, Yersinia.

DNS attacks

  • Types: open resolver, stealth, domain shadowing, tunneling.
  • Open resolver — answers queries from anyone (e.g. 8.8.8.8). Vulnerable to:
    • Cache poisoning — spoofed RR info redirects users.
    • Amplification & reflection — attacker uses target’s IP; open resolver floods target.
    • Resource utilization — DoS consuming resolver resources.
  • Stealth techniques:
    • Fast Flux — DNS IPs change within minutes; botnets hide servers.
    • Double IP Flux — also changes the authoritative name server.
    • Domain Generation Algorithms — random domains as C&C rendezvous points.
  • Domain shadowing — stolen domain credentials → many hidden subdomains pointing to malicious servers.
  • DNS tunneling — non-DNS traffic inside DNS (TXT, MX, SRV, NULL, A, CNAME records). Data split into encoded chunks in subdomain labels → ISP recursive DNS → attacker’s authoritative server → commands in responses.
  • Stop tunneling: filter/inspect DNS, watch longer-than-average queries and suspicious names; Cisco Umbrella (formerly OpenDNS); Dynamic DNS domains = highly suspect.

DHCP

  • Normal: Discover (broadcast) → Offer (unicast) → Request (broadcast) → ACK (unicast).
  • DHCP spoofing — rogue server gives wrong default gateway (MiTM), wrong DNS server, or wrong IP address (DoS).

4.2Enterprise Services

Web attacks

  • Stages: compromised page → redirects → drive-by download → exploit kit (often PHP) scans OS/Java/Flash → downloads exploit → payload → malware runs.
Status codeMeaning
1xxInformational (provisional)
2xxSuccessful
3xxRedirection

  • Defense: patch OS/browsers, web proxy (Cisco Cloud Web Security, WSA), educate users. OWASP Top 10 = most exploited web app risks.
  • Malicious iFrame — loads page from attacker’s server, can be a few pixels. Prevent: web proxy, devs avoid iFrames, Cisco Umbrella, user awareness.
  • HTTP 302 cushioning — chain of 302 Found redirects to exploit page.
  • Domain shadowing — sequence: site compromised → 302 cushioning → shadowed domain → exploit kit landing page → malware. Prevent: secure domain accounts (strong passwords, 2FA), check for unauthorized subdomains.

Email threats

  • Attachment-based attacks, email spoofing (forged sender), spam, open mail relay (SMTP server anyone can use — never configure), homoglyphs (O vs 0, l vs 1).
  • Defense: patch SMTP, Cisco Email Security Appliance (ESA), educate users (last line of defense).

Databases and scripting

  • Code injection — commands executed on server OS through vulnerable app (e.g. PHP in input field).
  • SQL injection — SQL in input; read/modify data, admin operations, OS commands. Cause: no input validation.
  • XSS — scripts injected into pages run in client browser.
    • Stored (persistent) — on server, hits all visitors.
    • Reflected (non-persistent) — in a link; victim must click.

4.3Mitigating Common Network Attacks

  • Best practices: written security policy, social engineering education, physical access control, strong passwords, encrypt data, firewalls/IPS/VPN/antivirus, tested backups, shut unused services/ports, patch weekly/daily, security audits.
  • Mitigation = countermeasures.
  • Antivirus — host-based, most widely deployed; auto-updates are the most critical requirement; does not stop viruses entering the network. Perimeter devices can drop known malware by IOC. No technique is 100% effective.

Worm mitigation (4 phases)

  • Containment — limit spread; segment network; inbound+outbound ACLs.
  • Inoculation — patch uninfected systems.
  • Quarantine — find and isolate infected machines.
  • Treatment — disinfect, patch; reinstall if severe.

Reconnaissance, access, DoS

  • Recon detected by alarms (e.g. ICMP requests/sec). Cisco ASA = standalone IPS; Cisco ISR = network-based IPS with software.
  • Mitigate recon: authentication, encryption (sniffing useless), anti-sniffer tools, switched infrastructure, firewall + IPS.
  • Port scanning cannot be prevented, only limited. Ping sweeps stopped by disabling ICMP echo on edge routers (lose diagnostics).
  • Access attacks: strong passwords (≥ 8 chars, mixed), lock accounts after failed logins, principle of minimum trust, encryption, MFA, review logs.
  • DoS signs: user complaints, slow network; use network utilization software / behavior analysis.
  • Antispoofing: port security, DHCP snooping, IP Source Guard, Dynamic ARP Inspection (DAI), ACLs.

  • 802.3 = wired Ethernet; 802.11 = WLAN.

  • WLANs: connect via AP/wireless router, battery devices, different frame format, more privacy issues.
  • 802.11 frame: Frame Control, Duration, Address1 (receiver), Address2 (transmitter), Address3 (destination, e.g. router), Sequence Control, Address4 (ad hoc only), Payload, FCS.
  • WLAN = half-duplex, shared media → can’t detect collisions.
  • CSMA/CA: listen → RTS to AP → CTS from AP (none = wait random time) → send → every transmission acknowledged (no ACK = collision assumed).
  • Association: discover → authenticate → associate. Parameters: SSID (one SSID per VLAN), password, network mode (802.11a/b/g/n/ac/ad, Mixed), security mode, channel.
  • Passive mode — AP sends beacon frames (SSID, standards, security).
  • Active mode — client sends probe request; needed when beacons disabled.
  • WLC (Wireless LAN Controller) centralizes management; APs become LWAPs (lightweight) that only forward data.

5.2WLAN Threats

  • Threats: interception of data (encrypt), wireless intruders (authenticate), DoS, rogue APs (management software).
  • DoS causes: misconfiguration, malicious interference, accidental interference (microwaves, cordless phones). 2.4 GHz more prone to interference than 5 GHz.
  • Rogue AP — unauthorized AP; capture MACs/data, MiTM. Personal hotspot can be a rogue AP. Prevent: WLC rogue AP policies + spectrum monitoring.
  • Evil twin AP — same SSID as legit AP, stronger signal; popular at free Wi-Fi spots. Defeat: authenticate users, monitor for abnormal devices.

5.3Secure WLANs

  • SSID cloaking (disable beacons) and MAC filtering — weak: SSIDs discoverable, MACs spoofable.
  • 802.11 original authentication: Open system (no security; use VPN) and Shared key.

  • WPA2-Personal — PSK, no server. WPA2-Enterprise — RADIUS server + 802.1X with EAP.
  • TKIP — WPA; legacy support; adds MIC (Message Integrity Check).
  • AES — WPA2; uses CCMP.
  • RADIUS: UDP 1812 (authentication), 1813 (accounting), or 1645/1646. Shared key authenticates AP to RADIUS (not configured on client).

  • WPA3-Enterprise — 802.1X/EAP, 192-bit suite, CNSA.
  • Open networks (WPA3) — no auth but OWE encryption.
  • IoT onboarding — DPP (Device Provisioning Protocol) with QR code; replaces vulnerable WPS.
Module 6

Network Security Infrastructure

6.1Security Devices

Firewalls

  • Properties: resistant to attacks, only transit point, enforce access control policy.
  • Benefits: hide sensitive hosts, sanitize protocol flow, block malicious data, simplify management.
  • Limitations: misconfig = single point of failure, some app data can’t pass securely, users bypass, slower performance, tunneled traffic.

Security architectures

  • Private/public — inside → outside permitted & inspected; outside → inside blocked.
  • DMZ — inside, outside, DMZ interfaces. Private → DMZ/public: permitted. DMZ → private: blocked. Public → DMZ: selectively permitted (email, DNS, HTTP/HTTPS). Public → private: blocked.
  • ZPF (zone-based policy firewall) — zones = groups of interfaces. Same zone: passes freely. Zone-to-zone: blocked by default (deny any). Exception: self zone (the router itself; no policy by default).

IDS / IPS

  • Deployed as sensors: router with IOS IPS, dedicated appliance, module in ASA/switch/router.
  • Signature — set of rules to detect malicious activity. Atomic = single packet; composite = multi-packet.

Specialized appliances

  • AMP (Advanced Malware Protection) — before, during, after an attack (continuous file analysis, retrospective alerts); uses Talos.
  • WSA (Web Security Appliance) — secure web gateway; blocks risky sites. CWS (Cloud Web Security) protects users outside the network; functions: web filtering + web security.
  • ESA (Email Security Appliance) — global threat intel (Talos), spam blocking (sender reputation + deep analysis), AMP (Sourcefire), outbound message control.

6.2Security Services

  • ACL — permits/drops packets by header info; limits traffic, flow control, basic security, filters by type, screens hosts, classifies traffic.
  • Standard ACL — source IPv4 only. Extended ACL — protocol, source/destination IP, source/destination ports.
  • Numbered or named; ACL logging; allow only established TCP (ACK/RST set).
  • SNMP — manager (in NMS) & agents; MIB stores device data on agent; get (collect), set (change), traps (agent → manager).
  • NetFlow — Cisco; statistics on IP flows → NetFlow collector. Original NetFlow 7 fields: src IP, dst IP, src port, dst port, Layer 3 protocol, ToS, input interface.
  • Port mirroring — switch copies traffic to a port with a monitor (sniffer/IDS).
  • Syslog — most common way to access system messages; functions: gather logs, select type, specify destination.
  • NTP — synchronize time (manual is not ideal). Hierarchy of strata:
    • Stratum 0 — authoritative high-precision sources.
    • Stratum 1 — directly connected to stratum 0; primary standard.
    • Stratum 2+ — sync from stratum 1; can serve stratum 3.
    • Max hop count 15; stratum 16 = unsynchronized.
  • AAA: Authentication (who you are), Authorization (what you can do: “student can access serverXYZ using SSH only”), Accounting (what you did: “… for 15 minutes”).

7.2Windows Architecture and Operations

  • HAL (Hardware Abstraction Layer) — handles communication between hardware and kernel.
  • Kernel mode — OS code; unrestricted hardware/memory access; crash = whole system. All kernel code shares one address space.
  • User mode — apps; no direct hardware access; crash limited to app; own private address space.
  • Drivers can run in either mode.

File systems

  • NTFS: large files, recovery, security descriptors (ownership & permissions to file level), encryption, MACE timestamps (Modify, Access, Create, Entry modified — forensics).
  • Order: partition → format.
  • NTFS structures: Partition Boot Sector (first 16 sectors, location of MFT), MFT (Master File Table: locations & attributes of all files), System Files (hidden), File Area.
  • Formatting doesn’t remove all data → secure wipe.
  • ADS (Alternate Data Streams) — data in $DATA attribute; hidden extra streams (file.txt:ADS) can hide malware; seen with dir /r.

Boot

  • BIOS (1980s) — POST → MBR loads OS.
  • UEFI — replaces BIOS; boots .efi files from EFI System Partition (ESP); boot code in firmware → protected mode, more secure.
  • Then: Bootmgr.exe (real → protected mode, reads BCD) → Winresume.exe + Hiberfil.sys (hibernation) or Winload.exe (cold start; uses KMCS to verify signed drivers) → Ntoskrnl.exe (kernel + HAL) → SMSS (user environment, Winlogon).

Startup and shutdown

  • Auto-start registry keys: HKEY_LOCAL_MACHINE (services at boot), HKEY_CURRENT_USER (at user logon). Entry types: Run, RunOnce, RunServices, RunServicesOnce, Userinit.
  • Msconfig.exe tabs: General (Normal/Diagnostic/Selective), Boot (Safe boot), Services, Startup, Tools.
  • Shutdown closes user mode first, then kernel mode. Options: Shutdown, Restart, Hibernate.

Processes, memory, registry

  • Process = running program; thread = executable part of a process; threads of a process share its address space. Services = background processes.
  • Virtual address space per process: 32-bit = 4 GB, 64-bit = 8 TB. User processes access kernel resources via a process handle.
  • RAMMap (Sysinternals) — view memory allocation.
  • Registry — hierarchical DB: hive → key → subkey → value; up to 512 levels. New hives can’t be created. Edit with regedit.exe.

7.4Windows Security

Module 9

System and Endpoint Protection

9.1Defending Systems and Devices

  • OS hardening: remove unneeded programs/services, timely patches, systematic update procedure, baseline to compare performance.
  • Rogue antivirus — fake Windows-like warnings that install malware.
  • Fileless malware — lives in memory, uses legitimate programs (PowerShell), no footprint, ends on reboot.
  • Scripts (Python, Bash, VBA macros) can be malware. Remove unapproved software.
  • Patch — code update; service pack — combined patches. Test patches before deploying. Patch management tool benefits: approve/decline, force updates by date, reports, local update server, users can’t bypass. Update third-party apps too (Adobe, Java, Chrome).

Endpoint security

  • Host-based firewall — restricts device traffic; inbound rules (e.g. Windows Firewall).
  • HIDS — monitors system calls, file access, registry; logs locally; resource-intensive; can’t see traffic that doesn’t reach host.
  • HIPS — detects known attacks & anomalies; alarm, log, reset connection, drop packets.
  • EDR — continuously monitors, analyzes and responds; finds threats (antivirus only blocks).
  • DLP — prevents sensitive data loss/misuse.
  • NGFW — firewall + filtering such as IPS with deep packet inspection (DPI).

Encryption and boot

  • EFS — encrypt files/folders. FDE — whole drive; Windows uses BitLocker (needs TPM chip in BIOS: stores keys, certificates, passwords).
  • BitLocker To Go — removable drives, password, no TPM. Self-encrypting drive — encrypts automatically.
  • Boot integrity — system not altered while OS loads. UEFI preferred over BIOS (64-bit mode).
  • Secure Boot — firmware checks signatures of boot software.
  • Measured Boot — stronger; measures each component, stores in TPM log, remote attestation; antimalware loads earlier.

Apple security

  • Secure Enclave (security hardware, AES engine), FileVault (encrypted storage), Secure boot (Boot ROM), secure biometrics, Find My Mac (locate, lock, erase), XProtect (signature antimalware), MRT (Malware Removal Tool), Gatekeeper (only signed, notarized software).

Physical protection

  • Cable locks, locked telecom rooms, Faraday cages (block EM fields).
  • Keyed lock (easy to force), deadbolt, cipher lock (button code, time limits, logging).
  • RFID — radio tags without battery; asset tracking, wireless locks.

9.2Antimalware Protection

  • Endpoints — hosts that access or are accessed by others (incl. IoT, VPN clients).
  • Stats: ransomware attack every 11 seconds by 2021; $6 trillion annual cost; 8–10% of spam malicious; malware changes in < 24 hours.
  • Internal LAN elements to secure: endpoints and network infrastructure (switches: MAC table overflow, spoofing, DHCP, LAN storm, STP, VLAN attacks).
  • Antivirus detection: signature-based (known malware), heuristics-based (general features), behavior-based (suspicious behavior).
  • Agent-based — runs on each host. Agentless — central scanning; good for VMs (VMware vShield).
  • Host-based firewalls: Windows Defender Firewall, Linux iptables, TCP Wrappers.
  • Host-based security suites: antivirus, anti-phishing, safe browsing, HIPS, firewall + telemetry (logging). AV-TEST reviews products.
  • Network-based protection: AMP (endpoint malware protection), ESA (email filtering), WSA (web filtering, blocklists, acceptable use), NAC (only authorized, compliant systems connect).

9.3Host-Based Intrusion Prevention

  • Host firewall logs: date/time, allowed/denied, IPs, ports. Distributed firewalls = host firewalls + central management.
  • Windows Defender Firewall — since XP; profiles Public (restrictive), Private, Domain (trusted business network).
  • iptables — Linux Netfilter rules. nftables — successor; virtual machine in kernel. TCP Wrappers — rule-based access control & logging by IP and service.
  • HIDS — log analysis, event correlation, integrity checking, policy enforcement, rootkit detection, alerting; antimalware + firewall; agent-based.
  • Signatures fail against zero-day and polymorphic malware → additional methods:
    • Anomaly-based — compare to learned baseline; many false results.
    • Policy-based — predefined rules; violations trigger action.
  • HIDS products: Cisco AMP, AlienVault USM, Tripwire, OSSEC (manager + agents for Mac/Windows/Linux/Solaris; syslog, file integrity, rootkit detection).

9.4Application Security

  • Attack surface components (SANS): network, software, human.
  • Blocklist — apps not allowed. Allow list — only apps allowed (based on security baseline). Website blacklists from services (Cisco Firepower + Talos; Spamhaus).
  • Sandboxing — run suspicious files in a safe environment. Cisco AMP tracks file trajectory & retrieves files; Cisco Threat Grid Glovebox sandbox.
  • Cuckoo Sandbox (free, local); online: VirusTotal, Joe Sandbox, CrowdStrike Falcon Sandbox, ANY.RUN (interactive, maps to MITRE ATT&CK).

Cybersecurity Principles, Practices, and Processes

10.1The Three Dimensions

  • Cybersecurity cube:
    • Security principles (CIA) — confidentiality, integrity, availability.
    • Data states — in transit, at rest (storage), in process.
    • Safeguards — technology, policy & practices, people (education, training, awareness).
  • Confidentiality — prevents disclosure to unauthorized people/processes.
  • Integrity — accuracy, consistency, trustworthiness of data across its lifecycle.
  • Availability — accessible by authorized users when needed.
  • Tokenization — confidentiality without encryption: random token replaces data; keeps format (databases, card payments).
  • DRM — protects copyrighted material (music, films, books). IRM — protects organization documents/email; owner controls access. Both use encryption.
  • Integrity methods: hashing, data validation checks, consistency checks, access controls.

  • Availability measures: equipment maintenance, OS/software patches, backup testing, disaster planning, new technology, activity monitoring, availability testing (port scans, vulnerability scans, pentests).

10.2States of Data

  • Data at rest storage:
    • DAS — attached to one computer (HDD, USB); not shared by default; hardest to manage.
    • RAID — multiple disks seen as one; performance + fault tolerance.
    • NAS — network device, centralized, scalable.
    • SAN — network-based storage, high-speed interfaces, many servers.
    • Cloud storage — Google Drive, iCloud, Dropbox.
  • Network storage (RAID, SAN, NAS) more secure but complex; failure = bigger risk.
  • Data in transit: sneaker net (removable media; can’t be eliminated), wired (copper, fiber; LAN/WAN), wireless (larger attack surface).
  • Protect in transit: confidentiality (VPN, SSL, IPsec), integrity (hashing, redundancy), availability (mutual authentication against rogue devices).
  • Data in process: input (entry errors, mislabeling, sensors), modification (encoding, compression, encryption; data corruption), output (printers, displays; wrong delimiters).

10.3Cybersecurity Countermeasures

  • Software: software firewalls, network/port scanners, protocol analyzers (signature analyzers), vulnerability scanners, host-based IDS.
  • Hardware: firewalls, proxy servers (one organization-wide IP, masks origin), hardware-based access control (biometrics), network switches.
  • Awareness: training in onboarding, tie to performance reviews, gamification (capture the flag), online courses. Program depends on environment, threat level, data. People are the first line of defense.
  • Security policy — objectives, rules of behavior, system requirements; shows commitment, sets rules, ensures consistency, defines legal consequences, gives staff management backing.
  • Policy types: identification & authentication, password, acceptable use (AUP), remote access, network maintenance, incident handling.
  • Standards — mandatory, ensure consistency (e.g. 8+ chars, change every 30 days, history of 12).
  • Guidelines — suggestions, flexible, not mandatory; best practices; sources: NIST, NSA, Common Criteria. Example: “I have a dream” → Ihv@dr3@m.

Understanding Defense

11.1Defense-in-Depth

  • Identify assets (greatest = data), vulnerabilities, threats.
  • Assets form the attack surface. Asset management = inventory + policies to protect.
  • Asset classification steps: 1) category (information, software, physical, services); 2) owner of each asset; 3) criteria (confidentiality, value, time, access rights, destruction); 4) classification schema.
  • Asset standards — specific hardware/software products; non-standard = costly, more expertise.
  • Asset lifecycle: procurement → deployment → utilization (longest) → maintenance → disposal (wipe data).
  • Threat identification questions: vulnerabilities? who would exploit? consequences?
  • e-banking threats: internal compromise, stolen customer data, phony transactions (external server or stolen PIN/smart card), insider attack, input errors, data center destruction.

Defense-in-depth

  • Multiple layers at edge, inside network, endpoints.
  • Edge router (1st line) → firewall (2nd; stateful, blocks outside-initiated connections, authentication proxy) → internal router (final filtering). Plus IPS, AMP, content security, NAC.
  • Failure of one safeguard doesn’t affect others.
  • Security onion — peel layers one by one to reach data.
  • Security artichoke — borderless networks; attacker removes only some “leaves” (e.g. mobile devices); benefits the attacker.
  • Strategies:
    • Layering — multiple defenses, each harder.
    • Limiting — minimum access needed (permissions, procedures).
    • Diversity — different layers/vendors/algorithms.
    • Obscurity — hide OS/equipment info; no details in error messages.
    • Simplicity — simple inside, complex outside.

11.2Cybersecurity Operations Management

  • Configuration management — identify, control, audit changes to a baseline configuration (template). Docs: network maps, naming conventions, IP schema.
  • Log — records events. Audit log = authentication attempts; access log = file requests. Log management: generate, transmit, store, analyze, dispose.
  • OS logs — client requests/server responses, usage info. Application security logs — from security software; auditing, trends, compliance.
  • Packet analyzer (sniffer) — traffic logging, problem analysis, misuse/intrusion detection, isolate exploited systems.

11.3Security Policies, Regulations, and Standards

  • Business policies: company (conduct, dress code), employee (HR: salary, vacations), security (objectives, rules, requirements; constantly evolving).
  • Security policy benefits: commitment, expected behavior, consistency, legal consequences, management backing; baseline for audits.
  • Policies included: identification & authentication, password, AUP (= appropriate use policy; explicit; every employee signs, kept for duration of employment), remote access, network maintenance, incident handling.
  • BYOD — own devices; benefits: productivity, lower costs, mobility, hiring appeal; risk: data breaches, liability.
  • BYOD policy: goals, who, which devices, access level, security staff rights, regulations, safeguards if compromised.
  • BYOD best practices: unique passwords, manual Wi-Fi/Bluetooth control, updates, backups, Find my Device (remote wipe), antivirus, MDM (Mobile Device Management).
  • INFOSEC professionals must know laws & ethics. Compliance regulations depend on organization type and data handled.

  • Provisioning = create/update software; deprovisioning = remove.
  • Secure coding:
    • Normalization — converts input to simplest form, unique binary representation; detects malicious input.
    • Stored procedure — precompiled SQL in DB; less traffic, faster.
    • Obfuscation — hides data with random characters. Camouflage — replaces with realistic fake data. Prevent reverse engineering.
    • Code reuse, SDKs/third-party libraries — faster but shared vulnerabilities.
  • Input validation — prevents malformed data (e.g. modified confirmation URLs flooding newsletter DB).
  • Validation rules: size, format, consistency, range, check digit (ISBN: multiply ×10…×2, sum, add digit to reach multiple of 11).
  • Integrity check uses a hash function; checksum = sum compared at both ends. Hashes: MD5, SHA-1, SHA-256, SHA-512.
  • Version control — two users can’t edit the same object at once (second gets read-only).
  • Authorization — need-to-know (read-only permissions).
  • Code signing — proves software is authentic and unchanged.
  • Secure cookies — sent only over HTTPS.
  • Application domain threats → fixes: unauthorized facility access (policies), downtime (business continuity & disaster recovery plans), NOS vulnerabilities (patching policy), unauthorized system access (MFA, logs), data loss (classification, backups), dev vulnerabilities (testing before launch).

12.3Network Hardening: Services and Protocols

  • NTP — needed for logs/certificates; use NTP authentication.
  • SSH (TCP 22) encrypted vs Telnet (TCP 23) plaintext. SCP — secure file copy over SSH.
  • SNMPv3 — encrypted, integrity.

12.6Cybersecurity Resilience

  • High availability principles: eliminate single points of failure, reliable crossover, detect failures as they occur.
  • Five nines = 99.999% availability = < 5.26 minutes downtime per year. Achieved with standardized systems, clustering, shared component systems.
  • Single point of failure — hardware, process, data or utility whose failure stops everything.
  • N+1 redundancy — at least one backup per component (spare tire); not fully redundant.
  • RAID — spreads data over drives; all except RAID 0 survive a disk loss. Hardware or software RAID.
    • Mirroring — duplicate on second drive.
    • Striping — data across drives.
    • Parity — striping + checksums on another drive.
  • STP (Spanning Tree Protocol) — prevents loops; blocks redundant paths, unblocks on failure.
  • Router redundancy — virtual router IP as default gateway; standby takes over = first-hop redundancy.
  • Location redundancy: synchronous (real time, high bandwidth, sites close), asynchronous (near real time, less bandwidth, sites far), point-in-time (periodic, least bandwidth).
  • Resiliency — methods to make a system tolerant of failure.
  • Application resilience (cost/complexity rising): backup & restore → cluster architecture → fault-tolerant hardware.
  • IOS resilient configuration — secure copy of IOS image + running config = primary bootset (can’t be removed).
  • Backups: full + partial (more partials = slower restore), off-site rotation, password-protected, validate.
  • HA clusters (identical servers, shared storage), fault tolerance (data mirroring), system resiliency (data and services stay available under attack).
  • Power rules: separate supply for data center, redundant feeds from 2+ substations, power conditioning, backup power, UPS.

12.7Embedded and Specialized Systems

  • Stuxnet targeted SCADA (part of ICS). SCADA wasn’t designed for Internet → now connected → vulnerable. Defense: separate SCADA network from LAN.
  • IoT — expands attack surface; IoT botnets = huge DDoS. Ensure firmware updates; change default credentials. Data growth = Big Data.
  • Embedded systems — vulnerable to timing attacks = side-channel (timing, power, EM leaks, sound).
  • SoC (System on Chip) — SFF modules (Raspberry Pi, Arduino), FPGA (reprogrammable in field); often poor authentication, unpatchable → implied trust.
  • RTOS — real-time OS for IoT (timing over throughput). Vulnerabilities: code injection, DoS, priority inversion.
  • VoIP — phone + adapter, VoIP phone, or softphone. Secure: encrypt voice packets, SSH on gateways, change default passwords, IDS (ARP poisoning), strong auth vs registration spoofing, proxy impersonating, call hijacking, VoIP-aware firewalls.
  • Special-purpose: medical (pacemakers, insulin pumps; NFC), automotive (tracking, jamming, spoofing → secure design, encryption, firewall), aviation (hard-coded credentials, backdoors), UAV/drones (hijacking, GPS spoofing, jamming, deauth).
  • Deception: honeypot (decoy server), honeynet (many honeypots), honeyfiles (dummy files), DNS sinkhole (blocks resolution of malicious names).
Module 13

Access Control

13.1Access Controls

  • Physical — guards, fences, motion detectors, laptop locks, locked doors, swipe cards, guard dogs, cameras, mantraps, alarms.
  • Logical — encryption, smart cards, passwords, biometrics, ACLs, protocols, firewalls, routers, IDS, clipping levels (error thresholds before alert).
  • Administrative — policies (intent), procedures (detailed steps), hiring practices, background checks, data classification, security training, reviews.
  • AAA: authentication (verify identity), authorization (what resources/operations; ACL; time limits), accounting (track actions; auditing). Like a credit card.
  • Authentication factors: something you know (password), have (token, card), are (fingerprint). 2FA = two of them.
  • Identification — enforces authorization rules; unique identifier (username, PIN, smart card, biometric).
  • Federated identity management — same credentials across multiple enterprises (social login, SSO); cascading risk; protect by tying login to an authorized device.
  • Passwords: ≥ 8 characters, mixed types, different per system, use a password manager.
  • Smart card — chip that processes/stores data with encryption. Security key fob — keyring device for 2FA.
  • Biometrics: physiological (fingerprint, DNA, face, hand, retina, ear) and behavioral (gestures, voice, gait, typing rhythm).
  • MFA — ≥ 2 methods (password + phone PIN; ATM card + PIN). 2FA is a type of MFA.
  • Authorization is automatic after authentication. Group membership policy (by group) vs authority-level policy (by position).
  • Accountability — trace action to person/process; logs (failures = hacking attempts); data retention, media disposal, compliance.

13.2Access Control Concepts

  • Zero trust — “never trust, always verify”; every access decision point is a perimeter; limits lateral movement.
  • Pillars: workforce (users & devices), workloads (apps, APIs, microservices, containers), workplace (all devices incl. IoT).

13.3Account Management

  • Don’t share privileged/admin accounts; admin account only for administration. Replace default accounts; all accounts need passwords.
  • Lifecycle: create identity profile (organization = IdP, Identity Provider), disable unused accounts, least privilege, review access, time-of-day and location restrictions.
  • Geofencing (action on entering/leaving area), geolocation (device location), geotagging (location tag on e.g. photo).
  • Privileged accounts: reduce number, least privilege, revoke on leave, no shared accounts/credentials, secure storage, rotate passwords every 30–60 days, record sessions, log activity, alerts, disable inactive, MFA for admin, gateway to sensitive assets.
